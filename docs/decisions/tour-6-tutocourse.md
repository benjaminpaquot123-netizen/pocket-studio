# Décisions du lot « tutocourse » (tour 6, 2026-11-13)

- 2026-11-13 · tour-6-tutocourse · Les regards du tuto sur le projet se font **un à la fois** : demandés par un canal qui n'en garde qu'un en attente (`TutoController.look()`), faits par une seule coroutine (`looks()`). Raison : ils partaient de cinq endroits (les modifications une fois posées, l'arrivée sur une étape, le bouton de l'étape, la fin de « Montre-moi », le démarrage) et travaillaient côte à côte hors du fil principal ; sur une machine lente, une réponse sur un projet d'avant arrivait la dernière et défaisait ce qu'une plus récente avait dit. Retour arrière : revenir le commit « vert: the tutorial's looks at the project cross each other ».
- 2026-11-13 · tour-6-tutocourse · Une réponse ne compte que si l'étape, la progression et le projet n'ont pas bougé pendant que le regard travaillait ; sinon elle est jetée et le regard est refait sur ce qui est là. Raison : c'est la seule façon de ne jamais appliquer une réponse périmée, d'où qu'elle vienne. Un projet qui a bougé est regardé une fois ses modifications posées (le même délai que pour toute modification) : pas de « Bravo » au milieu d'un trait. Retour arrière : avec le précédent.

Conséquence voulue : les blocs de `check()` qui testent « rien trouvé » (le besoin, l'ordre, et le bloc « softSaid » du lot tuto3) restent justes tels quels.
